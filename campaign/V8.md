# V8 production coverage producer

`v8_coverage.py` invokes `cargo llvm-cov --branch` with a pinned nightly Rust
compiler and pinned LLVM tools, and records the observed LLVM versions as the
tools print them. It measures `--lib --tests` with locked,
offline dependencies for three tl-syntax feature configurations, tl-parse, and
the default and infinite feature configurations of tl-mltl and tl-rewrite.

The report retains each JSON export and process streams by SHA-256. It records
the exact four source revisions and Cargo.lock digests, command, compiler and
coverage tool versions, feature set, test selection, production source line and
branch totals, and every uncovered branch location in critical operator and
typed-refusal files. Test, generated, and dependency files are excluded from
the production totals. An uninstrumented critical group or an uncovered
critical branch keeps the V8 target open until an exact infeasibility review
is accepted. The coverage result is a measurement, not a semantic-correctness
claim.

LLVM can count several compiled instances of one source branch, and its JSON
export does not identify which source detail contributes to the file summary.
V8 reports every named uncovered source location and every positive critical
file-summary deficit. Each is a separate review obligation. A file-summary
review has this shape:

```json
{
  "kind": "file_summary",
  "run": "parse-default",
  "file": "src/lexer.rs",
  "summary_missing_sides": 1,
  "source_file_sha256": "<exact source file SHA-256>",
  "raw_export_sha256": "<exact LLVM JSON export SHA-256>",
  "reason": "<substantive explanation of the infeasible compiled branch side>",
  "reviewer": "<named human reviewer>"
}
```

Existing source-location reviews keep their original shape. The v2 gate checks
both review types, source and export digests, and the exact file-summary
deficit independently of named gaps. A `0/0` or one-sided detail omitted from
the summary still needs a location review. A review does not reduce the
reported uncovered count. See `README.md` for review-input instructions.

Example (from a clean checkout with a writable, offline Cargo home):

```sh
python3 campaign/v8_coverage.py \
  --syntax /path/to/tl-syntax --parse /path/to/tl-parse \
  --mltl /path/to/tl-mltl --rewrite /path/to/tl-rewrite \
  --cargo-home /path/to/cargo-home \
  --raw-dir /path/to/v8-raw --output /path/to/v8-report.json
```
