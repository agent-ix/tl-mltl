# tl-mltl v0.1 architecture

## System Boundary

The trusted core consumes validated tl-syntax node tables and proposition
observations. Contextual entry points also consume the shared tl-syntax signal
catalog and optional requirement context. Pure modules implement horizon
analysis and three-valued temporal evaluation. Serialization, CLI dispatch,
contract-IR translation, and external execution sit outside that core and
cannot turn an error into a verdict.

## Views

The semantic view contains pure horizon and three-valued evaluation modules.
The interchange view contains strict serde documents and a thin CLI. The
integration view emits mapping manifests and compares externally supplied
monitor results without embedding an external engine. The context view binds
formula propositions to one unchanged shared catalog and carries its digest and
exact optional caller context through closed v2 native records.

## Decisions

Evaluation is total over closed traces by treating observations after closure
as false, while open prefixes use explicit unknown values. Release is defined
as the Boolean dual of Until, preventing divergent duplicate semantics.
Temporal expansion is checked against a configured work budget before loops.
Context-aware functions bind before semantic work. C2PO mapping uses exact
shared Boolean names only when they satisfy the pinned lexer and otherwise
refuses rather than renaming. Existing context-free v1 records remain unchanged.

## Risks

Naive interval expansion can be expensive; static analysis and hard limits fail
before impractical work. External monitor syntax/version drift is isolated by a
versioned mapping manifest and typed unsupported results.
Catalog/context substitution is isolated by complete-value request and result
digests and by refusing identity mismatch before differential agreement.
