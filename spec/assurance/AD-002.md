# AD-002: tl-mltl infinite-trace crate boundary

## System Boundary

tl-mltl's trusted core (AD-001) consumes only `tl-syntax.formula/v1` bounded
graphs and finite traces; it has no entry point for an `UnboundedInterval` or a
`tl-syntax.formula-unbounded/v1` document. Lasso-word acceptance, fairness
admission, and the inductive infinite-trace semantics tl-mltl#68 requested sit
entirely outside this boundary, in a named provider crate, `tl-live`, that
consumes the unbounded edition independently and registers against tl-syntax's
`tl-syntax.liveness/v1` capability on its own.

## Views

The bounded semantic view (AD-001) is unchanged: closed and prefix evaluation,
horizon analysis, and monitor mapping continue to operate only on
`tl-syntax.formula/v1`. A new, external view exists only as a naming
boundary: `tl-live` is referenced by identity wherever this crate's spec must
say where infinite-trace evaluation lives, but no module, dependency, or
feature flag in this crate reaches into it, and it reaches nothing in this
crate.

## Decisions

The crate boundary is decided from tl-mltl's own pre-existing scope, not
adopted as a new position: `spec/spec.md`'s Out-of-Scope section already
excluded "unbounded LTL" before this ticket, and the entire bounded-evaluator
architecture (closure-as-false, checked horizon expansion, pending-verdict
machinery) presupposes a finite trace throughout. quire-specification's own
AD-002 models infinite-trace analysis as provider-independent ("Providers
prove correspondence and soundness; finite monitors cannot overclaim"), and
tl-mltl is exactly the finite monitor that line describes, so the natural
extension is a separate provider crate rather than an in-repo facet.

`tl-live` is named here as a target-design reference, not an implemented
dependency: no `tl-live` repository or crate exists yet, and this PR creates
none. Naming it now lets tl-mltl#68's scope be routed to a concrete, stable
identity instead of an open question, and lets FR-028's registration boundary
be stated precisely.

## Risks

Until `tl-live` is implemented, tl-mltl#68's lasso/fairness/infinite-trace
request has no crate that satisfies it; this is the accepted, specified state
of this boundary decision, not a defect of this PR, whose own exit criterion
is only that `spec/spec.md` and tl-mltl#68 agree. Naming an unimplemented
crate risks drift if a differently-scoped or differently-named crate is built
instead; the control is that `tl-live` is referenced only by capability-facing
identity (the `tl-syntax.liveness/v1` registrant), so a rename before
implementation touches only these spec files, not tl-mltl's own evaluator.
