# AD-002: tl-mltl bounded and infinite feature boundary

## System Boundary

The bounded core consumes existing tl-syntax formula v1/v2 graphs and finite
closed, prefix or origin-complete histories. A non-default `infinite-trace`
Cargo feature exposes `tl_mltl::infinite`, which consumes the separate
`tl-syntax.formula-unbounded/v1`, lasso, fairness and partial-valuation
contracts under the TL-native `mltl.infinite-trace/v1` profile. QSL's
`quire.temporal.infinite-trace/v1` member is a correspondence, not the TL
profile or a compiled dependency.

## Views

The bounded view owns the existing closed, prefix and past entry points,
horizon analysis and monitor mapping. It neither imports nor dispatches into
`infinite`. The provider view owns lasso-word acceptance, fairness and
inductive infinite-trace semantics. It uses public tl-syntax contracts and
registers the one `tl-syntax.liveness/v1` backend; no second component
registers that capability in the same deployment. Only the provider can emit
a `proved` infinite-trace result. A finite prefix may refute an applicable
safety property but cannot prove liveness.

## Decisions

[ADR-003](../decisions/ADR-003-infinite-provider-feature-boundary.md) selects the
non-default feature-gated module for this prerelease system. The bounded API,
wire bytes and default dependency closure remain stable. The feature-enabled
build and default build are both tested. The feature does not promise `no_std`:
the released bounded crate already uses `std`, and a future `no_std` claim
requires separate work.

## Open Questions

No provider-location question remains. The V1 spec review must still validate
the exact error/result mapping, temporal laws and test matrix before
implementation begins.

## Risks

Cargo feature unification means a downstream feature selection can enable the
provider across one resolved graph. Consumers inspect and pin that feature
set; tl-rewrite does not enable it on its production dependency. Until the
module is implemented and registered, a formula-unbounded request settles
`unsupported` with the warning naming `tl-syntax.liveness/v1`. Resource
exhaustion settles `failed` with execution disposition `resource-incomplete`,
never proof.
