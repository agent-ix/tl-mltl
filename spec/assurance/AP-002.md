# TL Stage 1 five-repository release evidence profile

## Decision Boundary

The release owner decides whether one exact five-repository source graph has
enough V1 evidence for TL Stage 1 release preparation. The independent oracle
is a dev-only source and is part of evidence identity; it is not a production
dependency. Acceptance does not qualify R2U2 as a whole, a consuming monitor,
or a certified system.

## Impact Scenarios

The material scenarios are an incorrect Stage 1 verdict and a false completion
claim caused by stale, missing, or selectively omitted campaign evidence. Both
have deterministic pre-release controls in the exact source graph.

## Evidence Policy

The campaign report names each source revision, Cargo lockfile, input digest,
producer command, tool version, raw artifact digest, pass or refusal, and
unvisited population. Eleven milestone results remain distinct. A missing,
stale, noisy, failed, or incomplete milestone never becomes a pass through
aggregation. Quire validates static requirements and test traceability; Quoin
retains measurements and independent checker decisions. Neither substitutes
for the production tests, native tools, or owner decision.

## Measurement Policy

Quoin records MP-007 observations and displays the current measurement state.
Until an independent checker can produce a source-bound verdict, promotion
records the checker gap explicitly and uses the executable V1 campaign gate
for the fixed eleven-milestone rule. A Quoin collection or report cannot itself
turn an incomplete campaign into a pass or release code.

## Human Decision

Only `@kreneskyp` may accept the bounded source-release decision. A checker
verdict can inform that decision but cannot make it. An exception needs an
explicit owner, affected milestone, rationale, expiry, and acceptance record.

## Exceptions

No exception is implicit. An exception identifies an owner, affected milestone,
rationale, expiry, and a separate human acceptance record.
